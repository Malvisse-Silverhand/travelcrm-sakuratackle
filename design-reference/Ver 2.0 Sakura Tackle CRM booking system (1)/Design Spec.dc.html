Booking Landing Page Design Specification

Reference implementation: Laman Tempahan v2.dc.html. This document records the design tokens, component rules, responsive behaviour and accessibility requirements a developer needs to implement the page in WordPress (Breakdance or Elementor) without re-deriving decisions.

1. Design intent

The page borrows two proven patterns from the global travel-booking market and adapts them to a single-operator Malaysian fishing charter. From Booking.com: a search control placed immediately below the hero, overlapping it, so the first interaction is always "when and how many". From Airbnb: inventory presented as cards with real specifications, photography and price, filtered by the search rather than hidden behind a multi-step funnel. Content is reproduced verbatim from sakuratackle.com in Bahasa Malaysia; the interface chrome carries the visual system already established in the admin CRM, so the public page and the back office read as one product.

7. Responsive rules

Layout is driven by container queries on the page root, not viewport media queries, so the page behaves correctly inside a page builder canvas or a preview frame.

@container (max-width: 980px)  /* tablet and below */
  [data-split]   → single column
  [data-search]  → stacked fields, dividers hidden
  [data-fleet]   → 1 column
  [data-grid3]   → 2 columns
  [data-gallery] → 2 columns, spans reset, rows 150px
  [data-sec]     → 52px vertical padding
  [data-pad]     → 16px gutter

@container (max-width: 620px)  /* phone */
  [data-grid3]   → 1 column
  [data-specs]   → 2 columns

Verified at 1440px, 1024px, 768px and 390px. No fixed widths or white-space: nowrap on text containers; every grid track uses minmax(0, 1fr) so long boat names and BM strings cannot force horizontal overflow.

9. Performance

Two webfont families, four weights total. No icon library, no illustration assets, no third-party embed above the fold (the map is a static image linking out to Google Maps rather than an iframe). Gallery and testimonial images carry loading="lazy"; the hero image is the only eager request. Before launch, re-encode the source uploads as WebP at 1600px maximum width and add explicit width/height attributes to eliminate layout shift; the current build points at the live WordPress uploads, several of which are full-size PNG screenshots exceeding 1MB.
